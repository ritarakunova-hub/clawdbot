# Карта пользовательских намерений (intent map)

Справочник для бота: намерение посетителя → откуда брать ответ → что
делать дальше. Помогает боту не теряться и вести к нужному документу.

| Намерение посетителя (примеры фраз) | Источник ответа | Дальнейшее действие |
|---|---|---|
| «Что такое TAINA?» / «Чем вы занимаетесь?» | `01-o-taina.md` | Предложить стартовые кнопки |
| «Что такое RAG?» / «Как это работает технически?» | `02-produkty-i-rag.md` | Уточнить, про какой продукт именно интересно |
| «Подойдёт ли это моему бизнесу?» / описание своей ниши | `03-komu-i-zadachi.md` | Запустить мини-диагностику (документ 06) |
| Общий вопрос из FAQ (цена, сроки, процесс, данные) | `04-faq.md` | Ответить по сути, при интересе — вести к заявке |
| «Кто вы?» / «Кому можно доверять?» | `05-ob-osnovatele.md` | Коротко ответить, вернуться к теме бизнеса посетителя |
| «Покажи, как это работает» / «Приведи пример» | `06-scenarii-i-demo.md` | Провести мини-диагностику по описанному случаю |
| «Хочу оставить заявку» / «Как начать?» / явный интерес | — | Сразу вести к форме заявки на сайте |
| Вопрос не по теме TAINA | `07-tehnicheskie-granicy-rag.md` | Вежливо отказать, вернуть к теме |
| Просьба назвать точную экономию/ROI/скидку | `09-pravila-protiv-vydumok.md` | Отказаться называть цифру, объяснить почему, предложить диагностику |
| «Ты кажется бот?» / вопрос о природе бота | `07-tehnicheskie-granicy-rag.md` | Честно подтвердить |
| Явный сигнал, что автоматизация не нужна (единичные обращения, нет данных) | `03-komu-i-zadachi.md`, раздел «Кому не подойдёт» | Честно сказать, что не уверены, что даст эффект |

## Эскалация к форме заявки — когда предлагать

Предлагать форму заявки:
- Как только посетитель сам спрашивает про следующий шаг/цену/сроки
- После 3-4 содержательных реплик диалога, если интерес явно есть
- Всегда в конце мини-диагностики с положительным выводом

НЕ предлагать навязчиво на каждом сообщении — это раздражает и снижает
доверие.
