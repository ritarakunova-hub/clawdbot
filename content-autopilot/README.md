# TAINA Content Autopilot

Сервис проверяет календарь постов (по умолчанию ежедневно в 9:00 по Москве) и отправляет готовый текст в личный Telegram как черновик.

Публикация возможна только после явного нажатия «Опубликовать в VK и Telegram». Молчание никогда не считается согласием. Нет таймера, автопубликации или догоняющей публикации после перезапуска.

Если на дату указана только тема без готового текста, сервис присылает напоминание. Публикации не происходит.

## Защита согласования

- Webhook закрыт, если не задан TELEGRAM_WEBHOOK_SECRET; входящий заголовок сверяется с секретом Telegram.
- Действие разрешено только из исходного чата и от TELEGRAM_APPROVER_ID. Для личного чата пустое значение может использовать TELEGRAM_CHAT_ID. Для группового чата обязательно задайте числовой user ID.
- Перед внешними запросами черновик получает статус publishing. Повторный callback не должен повторно запустить тот же черновик.
- При частичном сбое обе площадки нужно проверить вручную. Нет слепой повторной отправки.
- После перезапуска старый черновик остаётся на ручном согласовании. Если сервис остановился во время запроса, статус переводится в needs_review; автоматического повтора нет.
- Старые pending-записи с таймером мигрируют в awaiting_approval; прежний срок автопубликации игнорируется.

## Переменные окружения

- TELEGRAM_BOT_TOKEN — токен бота.
- TELEGRAM_CHAT_ID — личный чат для черновиков и уведомлений.
- TELEGRAM_CHANNEL_ID — канал для согласованных постов.
- TELEGRAM_WEBHOOK_SECRET — обязательный секрет Telegram webhook (32–256 символов из латинских букв, цифр, `_` и `-`).
- TELEGRAM_WEBHOOK_URL — публичный HTTPS URL обработчика `/telegram/webhook`.
- ADMIN_WEBHOOK_SECRET — отдельный секрет для ручного запуска POST /check/now; без него endpoint закрыт.
- TELEGRAM_APPROVER_ID — числовой ID пользователя, которому разрешено подтверждать и отклонять посты.
- VK_GROUP_ID и VK_COMMUNITY_TOKEN — ID и токен сообщества VK.
- TIMEZONE и CRON_SCHEDULE — расписание; по умолчанию Europe/Moscow и 0 9 * * *.
- CONTENT_AUTOPILOT_DATA_DIR — необязательный путь к постоянному каталогу хранения pending.json.

Храните секреты только в переменных окружения хостинга или локальном .env. Не отправляйте токены в чат и не добавляйте их в GitHub.

## Проверка перед запуском и Telegram webhook

Перед подключением внешних каналов проверьте конфигурацию, календарь публикаций и права записи в каталог состояния:

    set -a && . ./.env && set +a
    node scripts/preflight.js

Укажите публичный HTTPS URL в `TELEGRAM_WEBHOOK_URL` внутри `.env`. Для регистрации используйте встроенный скрипт после загрузки переменных окружения:

    node scripts/set-telegram-webhook.js

Скрипт отправляет `setWebhook` через POST, проверяет ответ Telegram и не печатает токен или секрет. Не регистрируйте webhook командой, в которой токен или секрет прописаны непосредственно в URL или аргументах терминала.

## Локальный запуск

    cp .env.example .env
    # Заполните .env своими значениями; не отправляйте секреты в чат.
    npm install
    npm test
    npm start

Ручная проверка календаря (секрет берите только из локального окружения, не вставляйте его в переписку):

    set -a && . ./.env && set +a
    curl -X POST http://localhost:3000/check/now -H "x-taina-admin-secret: $ADMIN_WEBHOOK_SECRET"

## Хранение состояния и развёртывание

Ожидающий черновик хранится в data/pending.json. Для стабильной работы на сервере нужен постоянный каталог, который переживает пересоздание контейнера. Перед запуском нужно проверить, что хостинг действительно монтирует persistent volume или каталог, указанный в CONTENT_AUTOPILOT_DATA_DIR.

Сервис пока не развёрнут. До запуска нужно проверить постоянное хранилище, HTTPS webhook, права бота на публикацию, права токена сообщества VK, ограничения Telegram/VK и выполнить тесты на отдельном тестовом канале/сообществе, чтобы не публиковать случайный рабочий пост. Ручной endpoint /check/now закрыт отдельным ADMIN_WEBHOOK_SECRET.

## Календарь

Тексты и темы находятся в data/posts.json. Для готовой публикации поле `text` содержит основную версию для VK, а `telegramText` — отдельную короткую версию для Telegram. Обе версии показываются в черновике перед согласованием. Если `telegramText` не задано, в обе площадки отправляется `text`. Записи типа topic — это напоминания, а не готовые публикации.


## Развёртывание на VPS UFO.Hosting (Docker)

В репозитории добавлена отдельная конфигурация Docker Compose для VPS с Linux. Она не открывает порт приложения в интернет: порт 3000 привязан только к 127.0.0.1 и должен быть проксирован через уже настроенный веб-сервер панели с HTTPS.

Краткий порядок:

1. Установить Docker Engine и Compose Plugin по официальной инструкции UFO.Hosting для установленной версии Ubuntu.
2. Клонировать репозиторий и перейти в `content-autopilot`.
3. Создать `.env` из `.env.example`, заполнить настройки и права доступа; не коммитить этот файл.
4. Создать `data/` и дать UID 1000 право записи — контейнер работает от непривилегированного пользователя Node.
5. Запустить `docker compose up -d --build` и проверить `docker compose ps`, `docker compose logs --tail 50 app` и `curl http://127.0.0.1:3000/health`.
6. В панели домена настроить HTTPS reverse proxy на `http://127.0.0.1:3000`, после чего установить Telegram webhook на HTTPS URL `/telegram/webhook`.
7. Проверять публикацию сначала на отдельном тестовом канале/сообществе.

Подробные команды, резервное копирование и обновление — в `deploy/ufo-vps/README.md`. Не запускайте `docker compose down -v`: постоянные данные находятся в bind-mounted каталоге `data/`.
