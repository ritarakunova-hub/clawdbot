# TAINA Sales Engine — V1

Полностью рабочий код: поиск компаний → анализ Claude (факт vs гипотеза) →
детерминированный scoring → персональное сообщение → карточка в Telegram
с кнопками → ваше решение → сохранение в Google Sheets → **дальше сервис
сам ведёт лида по воронке** (следит за ответом, готовит follow-up,
закрывает без ответа) — от вас нужно только нажимать «Одобрить» на
том, что он предлагает отправить.

Никакого n8n, никакого GigaChat — весь пайплайн это один сервис на
Node.js, который вы один раз деплоите и дальше просто открываете
страничку с формой.

## Воронка — этапы сделки прямо в таблице

Колонка `status` в Google-таблице — это и есть воронка. Сервис двигает
лида по ней сам, по расписанию, но **ничего никогда не отправляет
без вашего клика** (кнопка «Одобрить» в Telegram — обязательный шаг):

```
Новый ─────────────────────────────► (score < 70, дальше не двигается)
  │ (score ≥ 70)
  ▼
Готов к проверке ──[вы: Отклонить]──► Отклонён (конец)
  │                ──[вы: Изменить]──► Нужна правка (правите текст в таблице сами)
  │ [вы: Одобрить]
  ▼
Отправлено ──(прошло FOLLOWUP_DAYS дней без ответа, сервис сам проверяет)──┐
  ▲                                                                        │
  │                                                                        ▼
  └────────────[вы: Одобрить follow-up]──── Готов к проверке (follow-up N) ◄─┘
                                                        │
                                          (после MAX_FOLLOWUPS попыток)
                                                        ▼
                                              Нет ответа (закрыт)
```

Как только вы вручную впишете в статус что угодно своё — например
`Клиент`, `Отказ`, `Переговоры` — сервис перестаёт трогать эту строку
автоматикой: воронка следит только за строками в статусе `Отправлено`.

## Как это работает для вас день за днём

1. Открываете сайт сервиса → вводите нишу и город → жмёте «Найти лидов»
2. Через 1-3 минуты в Telegram приходят карточки только по **хорошим**
   лидам (score ≥ 70)
3. Под каждой карточкой — кнопки **✅ Одобрить / ❌ Отклонить / ✏️ Изменить**
4. При «Одобрить» бот пришлёт готовый текст — копируете и отправляете
   тем каналом, который сами найдёте у компании (телефон/сайт/почта).
   Статус лида в этот момент становится `Отправлено` — с этого момента
   идёт отсчёт до follow-up.
5. Если через несколько дней ответа нет — **сервис сам** (по
   расписанию, раз в день) готовит короткое follow-up-сообщение и
   присылает его карточкой с теми же кнопками. Вы так же жмёте
   «Одобрить» и отправляете.
6. Если ответа нет после `MAX_FOLLOWUPS` попыток — лид автоматически
   закрывается статусом `Нет ответа (закрыт)`, сервис перестаёт его
   трогать.
7. Если человек ответил и у вас дальше идут переговоры — просто впишите
   в ячейку статуса что-то своё (`Клиент`, `Переговоры`, `Отказ`) —
   дальше это уже не забота автоматики, а ваша ручная работа по сделке.

Все компании (и хорошие, и слабые) сохраняются в таблице — повторный
прогон никогда не покажет вам одну и ту же компанию как новую.

## Что нужно сделать вам (без этого не заработает)

Все эти пункты — не мои ограничения, а то, что физически может сделать
только владелец аккаунтов.

### 1. Google-таблица (как в мини-CRM)

Создайте новую Google-таблицу (отдельную от мини-CRM — это разные проекты),
назовите лист `Лиды`. Первая строка — заголовки для вашего удобства:

```
id | domain | company | niche | city | source | contacts | site_summary | ai_analysis | score | score_reason | data_confidence | problem | solution | message | status | follow_up_count | first_contact_date | last_status_update | notes
```

Сервис сам генерирует `id` и заполняет остальные поля — руками ничего
вписывать не нужно.

**Сервисный аккаунт Google**: если вы уже создавали его для мини-CRM —
можно переиспользовать тот же (тот же `client_email`, та же
base64-строка ключа), просто дайте ему доступ **Редактора** и к этой
новой таблице тоже. Если ещё не создавали — шаги те же, что в
`mini-crm/README.md`, раздел «Шаг 2».

Скопируйте **ID этой таблицы** (из URL, между `/d/` и `/edit`).

### 2. Ключ Anthropic (Claude) — это я, но нужен ваш собственный ключ

Один и тот же ключ используется и для поиска компаний (обычный
веб-поиск, не через Google Maps/2ГИС/Яндекс.Карты — Claude сам ищет
сайты компаний в интернете и берёт адреса прямо из результатов поиска),
и для анализа/scoring/текстов сообщений. Отдельный аккаунт для поиска
заводить не нужно.

1. Зайдите на [console.anthropic.com](https://console.anthropic.com)
2. **API Keys → Create Key**
3. Это `ANTHROPIC_API_KEY`

Экономика: веб-поиск стоит $0.01 за один запрос, один прогон делает
несколько поисков с разными формулировками — расход в пределах
нескольких центов. Анализ каждой компании — ещё 1-2 обращения к Claude,
тоже доли цента. При 70 000 ₽ за проект это не заметно даже на сотнях
прогонов.

Честный минус веб-поиска: телефон компании он находит реже, чем
специализированные бизнес-справочники — иногда его придётся находить
вручную на сайте компании перед тем, как писать.

### 3. Telegram-бот

Если у вас уже есть бот из мини-CRM — можно использовать его же (или
создать отдельного, чтобы не путать уведомления двух разных проектов —
решать вам).

1. **@BotFather** → `/newbot` → получите `TELEGRAM_BOT_TOKEN`
2. Напишите боту любое сообщение, затем откройте
   `https://api.telegram.org/botВАШ_ТОКЕН/getUpdates` → найдите
   `chat.id` — это `TELEGRAM_CHAT_ID`
   (подробности — в `mini-crm/README.md`, раздел «Шаг 3»)

### 4. Деплой на Amvera

1. Создайте новое приложение на Amvera, подключите репозиторий, папка `sales-engine`
2. В **«Переменные и секреты»** добавьте (как секреты):
   - `ANTHROPIC_API_KEY`
   - `GOOGLE_SHEET_ID`
   - `GOOGLE_SERVICE_ACCOUNT_KEY_BASE64`
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
   - `TELEGRAM_WEBHOOK_SECRET` — придумайте пароль (например,
     сгенерируйте на [passwordsgenerator.net](https://passwordsgenerator.net))
   - `APP_USERNAME` и `APP_PASSWORD` — свои логин/пароль для формы,
     чтобы посторонние не могли жать «Найти лидов» за ваш счёт
   - `FOLLOWUP_DAYS` (по умолчанию 3), `MAX_FOLLOWUPS` (по умолчанию 2),
     `CRON_SCHEDULE` (по умолчанию `0 10 * * *` — каждый день в 10:00) —
     необязательные, можно не задавать, сработают значения по умолчанию
3. `git push` в отслеживаемую ветку → Amvera соберёт и запустит по `amvera.yml`
4. После деплоя Amvera покажет адрес, например `https://taina-sales.amvera.io`

### 5. Подключить кнопки Telegram к сервису

Чтобы нажатия «Одобрить/Отклонить» доходили до сервиса, один раз
скажите Telegram, куда их слать (замените токен, адрес и секрет на свои):

```
curl "https://api.telegram.org/botВАШ_ТОКЕН/setWebhook?url=https://ВАШ-АДРЕС-НА-AMVERA/telegram/webhook&secret_token=ВАШ_TELEGRAM_WEBHOOK_SECRET"
```

Выполните эту команду один раз (в любом терминале, хоть с телефона через
Termux, хоть попросите меня — это не секретный вызов, но токен в URL
всё равно никому не показывайте).

## Использование

Откройте `https://ВАШ-АДРЕС-НА-AMVERA/` (браузер спросит логин/пароль —
те, что вы задали в `APP_USERNAME`/`APP_PASSWORD`), заполните нишу и
город, нажмите «Найти лидов». Дальше просто ждите карточки в Telegram.

**Совет по нишам** — начните с 1-2 ниш из вашего исходного списка
(медицинские центры, сервисные бизнесы с большим потоком клиентов) в
одном городе, лимит 10 — посмотрите на качество карточек и score, прежде
чем расширять на другие ниши/города.

**Проверить воронку, не дожидаясь реальных дней** — на главной странице
есть кнопка «🔁 Проверить follow-up сейчас», запускает ту же проверку,
что идёт по расписанию. Чтобы прямо увидеть follow-up в деле при
тестировании, временно поставьте `FOLLOWUP_DAYS=0` в переменных Amvera —
тогда follow-up предложится уже на следующий день после «Одобрить», не
дожидаясь реальных 3 дней. После теста верните обратно на 3.

## Как устроен scoring (чтобы доверять цифрам)

Claude НЕ придумывает число 0-100 — это ненадёжно и невоспроизводимо.
Вместо этого он отвечает по 4 критериям (подходит ли ниша, есть ли
признаки повторяющихся обращений, есть ли масштаб/сеть, понятно ли
решение), для каждого — да/нет + уверенность. Итоговая цифра считается
прозрачной формулой в коде (`src/scoring.js`) — вы всегда можете
посмотреть, за что именно начислены баллы (колонка `score_reason` в
таблице и в карточке Telegram).

## Если что-то не работает

Смотрите логи в личном кабинете Amvera — там видно, на каком шаге
ошибка (поиск / анализ / запись в таблицу / Telegram). Пришлите мне
текст ошибки — поправлю точечно, а не буду предлагать переделать всё
заново.

## Локальный запуск для проверки

```
cp .env.example .env
# заполните .env своими значениями
npm install
npm test      # проверка логики без реальных API (Claude/Sheets/Telegram)
npm start     # http://localhost:3000
```

## Чего сознательно нет в V1 (следующие этапы)

- Триггеры продаж (найм сотрудников, рост филиалов, новости)
- Другие источники лидов кроме веб-поиска Claude
- Автоматическое определение "человек ответил" (сейчас это вы сами
  фиксируете, вписывая статус в таблицу)

Архитектура (отдельные модули `webLeadSearch.js`/`sheets.js`/`telegram.js`)
специально сделана так, чтобы это можно было добавить позже, не
переписывая всё с нуля.
