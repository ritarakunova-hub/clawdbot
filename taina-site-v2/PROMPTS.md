# Сборка сайта TAINA STUDIO по этапам

Последовательность промптов для Claude Code. Один промпт — один этап. После каждого этапа: проверьте глазами, что написано в отчёте, сделайте коммит, потом переходите дальше.

## Как начать
1. Создайте пустую папку `taina-site`, положите в неё `CLAUDE.md` и папку `reference` (с `taina-hero.html`).
2. Откройте папку в Claude Code и вставьте **Этап 0**.
3. В начало **каждого** промпта вставляйте «Шапку» ниже. Она заставляет Claude сначала изучить код и не ломать работающее.

## Шапка (вставлять перед каждым этапом)
```
Роль: senior frontend-инженер и creative developer. Проект — TAINA STUDIO, правила в CLAUDE.md.

Порядок работы:
1. Изучи текущий код и файлы, про которые сказано ниже. Перескажи мне в 5–7 строках, что уже есть.
2. Предложи короткий план (3–7 шагов) и подожди моего «ок». Если задача мелкая, делай сразу.
3. До изменений запусти npm run build и npm run check и скажи, что было зелёным.
4. Меняй малыми шагами, после каждого запускай сборку.
5. Не удаляй и не переписывай работающее без причины. Если нужно, объясни зачем.
6. В конце отчёт: что сделано, как проверить глазами на компьютере и на телефоне, что осталось, какие риски.
```

## Этап 0. Старт проекта
```
Цель: пустой проект, который собирается.

Шаг 0. Проверь, есть ли Node.js (LTS) и git. Если нет, объясни простыми словами, как поставить для моей системы, и подожди.
Задача:
- Создай проект Astro + TypeScript (минимальный шаблон) в текущей папке, не затирая CLAUDE.md и reference/.
- Подключи ESLint и Prettier, алиас @/ на src/, скрипты dev, build, preview, check, lint из CLAUDE.md.
- git init, .gitignore, первый коммит. Создай .env.example (пока пустой).
Критерии: npm run dev открывает пустую страницу, npm run build и npm run check проходят.
Не добавляй ничего лишнего: ни UI-фреймворков, ни анимационных библиотек.
```

## Этап 3. Перенос хиро
```
Цель: тот же первый экран, но как модули проекта.

Шаг 0. Прочитай reference/taina-hero.html целиком: шейдеры, порядок сцены, тайминги вступления, поведение при скролле и курсоре, уровни отказа. Сделай скриншоты эталона в 1440×900 и 390×844 (Playwright) и сохрани как эталоны.
Задача:
- Перенеси в src/scene/: renderer.ts, scenes/hero/*, materials/, shaders/*.glsl (импорт через ?raw), objects/ (ромб, листы, пыль, пол, кот).
- Three.js из npm, EffectComposer из examples/jsm. Логику не меняй, пока не совпали скриншоты.
- Грузи 3D через динамический import после первого отображения текста (LCP считается по тексту).
- Сохрани отказоустойчивость: если WebGL или скрипты не работают, заголовок и кнопка всё равно видны (уровни C и D).
- Ассет кота вынеси из data-URI в public/img/ как оптимизированный файл.
Критерии: визуально совпадает с эталоном на обоих размерах, ошибок в консоли нет, JS первого экрана ≤ 250 КБ gzip, при уходе с экрана рендер останавливается.
```

## Этап 4. Ядро движения
```
Цель: единый механизм для всех сцен.

Шаг 0. Изучи текущий цикл в scene/ и документ «Система движения» (его правила продублированы в CLAUDE.md).
Задача:
- loop.ts: один requestAnimationFrame, dt с ограничением 0,05, сглаживание k = 1 − 0.003^dt, реестр сцен с кэшированными top и len (пересчёт по ResizeObserver, без getBoundingClientRect в кадре). Обновляются только активная и соседняя сцены.
- scroll.ts: прогресс p сцены из нативного скролла, закрепление через CSS sticky.
- quality.ts: уровни A–D, автоснижение DPR (2 → 1,5 → 1 → 0,75) по среднему времени кадра за 90 кадров, ручной флаг ?debug с оверлеем (время кадра, DPR, уровень).
- Живое отслеживание prefers-reduced-motion; кнопка «Остановить анимацию» в подвале.
Критерии: скролл не перехватывается, в цикле нет чтения layout, сцены вне экрана не рендерятся, тест Playwright проверяет паузу и reduced-motion.
```

## Этап 5. Сцена «Проявка»
```
Цель: сцена 2 и мост из хиро.

Шаг 0. Изучи как хиро отдаёт управление (вспышка, финал скролла). Не меняй хиро без необходимости.
Задача (по документу «Система движения», сцена 2):
- Чёрный лист в центре проявляется по яркости от скролла, фраза сцены проявляется тем же световым фронтом.
- Слои: лист 0,4, рамка 0,6, камера едет вперёд на 0,6 единицы.
- Мост в сцену 3: луч расщепляется на три вертикальные полосы за 900 мс (inOut).
- Закреплённая секция 220vh. Вспышка хиро гаснет за первые 8% скролла.
Критерии: 60 fps на среднем Android (или честная оценка, если проверить негде), при reduced-motion остаётся статика.
```

## Этап 6. Три территории
```
Цель: сцена 3, выбор пути пользователем.

Шаг 0. Изучи секцию Territories из этапа 2 и ядро движения.
Задача:
- Закреплённая секция 300vh, горизонтальная лента, сдвиг 1:1 по скроллу (scrub).
- Центральный кадр: масштаб 1. Соседние 0,94 и чёрный слой поверх с прозрачностью 0,55 (без CSS-блюра).
- Внутри кадров: смыслы (призма со словами), образы (плёнка и видеопетля), системы (граф документов, по которому бежит свет запроса). Камера в кадре чуть облетает объект (±6°).
- Hover: затемнение 0,55 → 0 за 260 мс, объект ускоряется 1× → 2,2× за 400 мс. Клик раскрывает кадр на весь экран (FLIP, 700 мс) и запоминает выбор для формы.
- Телефон: три кадра друг под другом, вход 500 мс прозрачностью.
Критерии: работает клавиатурой (Tab, Enter), тексты кадров остаются в DOM.
```

## Этап 7. Демо ассистента
```
Цель: живой чат, который доказывает продукт.

Шаг 0. Изучи секцию Demo. Узнай у меня, есть ли адрес n8n-вебхука. Если нет, делай режим mock.
Задача:
- Контракт: POST /api/ask {question} → {answer, sources[], found: boolean}. Таймаут 12 с, повтор один раз, понятные тексты ошибок. Режим mock с записанными ответами включается автоматически при недоступности бэкенда.

- Анимация: луч ромба летит к листу с ответом (700 мс, inOut). Если ответа нет, луч возвращается за 500 мс, кот моргает 280 мс, текст «этого нет в моих данных» проявляется 300 мс.
- Строка приватности: демо работает на тестовой базе, ваши данные не нужны; в модель уходят вопрос и найденные фрагменты.
- Калькулятор: ползунок «часов в неделю на поиск ответов», формула на экране, без выдуманных «средних по рынку».
Критерии: работает без бэкенда (mock), ошибки показываются по-человечески, клавиатура проходит весь сценарий.
```

## Этап 8. Проект и Бегемот
```
Цель: сцены 5 и 6.

Шаг 0. Изучи секции Project и Behemoth и как устроены листы на GPU.
Задача:
- Проект: закреплённая секция 260vh, четыре шага по 65vh (было, увидели, сделали, получили). Хаос листов превращается в стеллаж на GPU через uniform uOrder, у каждого листа своя задержка. Свет меняется с красного на золотой. Текст шага заменяется перекрёстным появлением 400 мс.
- Показывай только реальные данные: один кейс, отзыв без названия. Вторую карточку сделай как «Проект 02 проявляется…».
- Бегемот: сцена 120vh. Свет падает до 8%, проявляются глаза, затем фраза «Я знаю кое-что, чего пока не знаете вы». Зрачки следят за курсором ±6 px. Финал: глаза приближаются, в зрачке загорается ромб, радиальный свет ведёт в «Пакеты».
Критерии: reduced-motion даёт статичные кадры, отзыв показывается только при пометке [ПОДТВЕРЖДЕНО].
```

- **Claude что-то сломал.** Скажите: «Откати последний коммит и объясни, что пошло не так». Поэтому работаем маленькими коммитами.
- **Слишком тяжело на телефоне.** Вернитесь к этапу 12 и не добавляйте новых эффектов, пока цифры не в норме.
- **Не понимаете отчёт.** Спросите: «Объясни проще и покажи, что мне проверить глазами».
