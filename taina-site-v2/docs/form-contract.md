# Контракт формы — что нельзя сломать на Этапе 10

Форма заявки ещё не готова (это отдельный Этап 10). Этот файл — шпаргалка
на будущее: как устроена форма на текущем сайте и что её принимает, чтобы
новая форма не сломала вашу таблицу заявок и Telegram-уведомления.

Здесь нет паролей, токенов и адресов серверов — только структура данных.

## Как это работает сейчас (production, `taina-site/index.html`)

1. Форма — обычный HTML с атрибутом `data-netlify="true"`. Netlify сама
   находит такие формы во время сборки сайта и начинает принимать заявки —
   без бэкенда на самом сайте.
2. Имя формы: **`taina-diagnostic`** (атрибут `name` на `<form>` и скрытое
   поле `form-name` с тем же значением — Netlify требует оба).
3. Скрытая ловушка от спам-ботов: поле `bot-field` (атрибут
   `netlify-honeypot="bot-field"` на форме). Реальные посетители его не
   видят и не заполняют.
4. Поля формы:
   - `name` — имя
   - `contact` — одно общее поле: телефон, почта или Telegram одной
     строкой
   - `message` — текст, необязательное поле
5. Отправка — через `fetch` на `/` (чтобы посетитель остался на странице и
   увидел «Спасибо» вместо служебной страницы Netlify), с fallback на
   обычную отправку формы, если JavaScript не сработал.
6. Дальше Netlify передаёт заявку в мини-CRM (`mini-crm/`) через Outgoing
   Webhook.

## Как мини-CRM разбирает заявку (`mini-crm/src/lead.js`)

Netlify заворачивает данные заявки в такую структуру:

```
{
  payload: {
    form_name: "taina-diagnostic",
    data: { name: "...", contact: "...", message: "..." }
  },
  site_url: "...",
  created_at: "..."
}
```

Парсер мини-CRM ищет поля по нескольким вариантам названия (регистр и
язык могут отличаться):

| Что ищет | Варианты названий поля |
|---|---|
| Имя | `name`, `Name`, `имя`, `Имя` |
| Почта | `email`, `Email`, `почта`, `Почта` |
| Телефон | `phone`, `Phone`, `телефон`, `Телефон` |
| Сообщение | `message`, `Message`, `сообщение`, `Сообщение`, `комментарий` |
| Общий контакт | `contact`, `Contact`, `контакт`, `Контакт` |

Если отдельных полей `email`/`phone` нет, а есть общее `contact` —
мини-CRM сама решает, это почта или телефон: смотрит, есть ли в строке
`@`. Так работает текущая форма (там одно поле «Контакт»).

Каждая заявка попадает строкой в Google-таблицу «Заявки» со столбцами:

```
name | email | phone | message | form_name | received_at | status | last_status_update | notes
```

`form_name` — это то самое имя формы (`taina-diagnostic`), по нему в
будущем можно будет отличать заявки с разных форм, если их станет
несколько.

## Что нужно сохранить на Этапе 10, чтобы не сломать таблицу

1. **Поле `contact` (или отдельные `email`/`phone`)** — если новая форма
   разделяет способ связи на «Telegram» и «почта» отдельными полями,
   мини-CRM их не найдёт автоматически (она ищет `email`/`phone`, не
   `telegram`). Проще всего — оставить одно поле `contact`, как сейчас, и
   класть туда либо Telegram, либо почту, что бы пользователь ни выбрал.
2. **Поле `name`** — оставить как есть.
3. **Поле `message`** — оставить как есть (необязательное).
4. **Имя формы** — если менять `taina-diagnostic` на другое имя, скажите
   заранее: это не сломает приём заявок (мини-CRM не завязана на конкретное
   имя формы), но изменится значение `form_name` в таблице — старые и
   новые заявки будет проще отличать, если вы будете об этом знать.
5. **honeypot** (`bot-field`) — стоит оставить, это защита от спама, на
   парсинг не влияет.

## Что добавится по плану (PROMPTS.md, Этап 10) и потребует внимания

Новая форма планирует поле **«что проявить»** (AI-аудит / образ или фильм /
пока не знаю) — такого поля сейчас нет ни в форме, ни в мини-CRM. Это
не сломает приём существующих полей, но:

- само это поле в таблицу пока писаться не будет (мини-CRM его не ждёт и
  проигнорирует, заявка не потеряется);
- если хотите видеть выбор в таблице — на Этапе 10 нужно будет добавить
  колонку и доработать `mini-crm/src/lead.js`, это отдельная маленькая
  задача, сделаем вместе с самой формой.

Также Этап 10 добавляет чекбокс согласия на обработку персональных данных
и предзаполнение из выбранной территории/пакета — это поля только для
интерфейса, в таблицу заявок по умолчанию не пойдут, если явно не попросите
их туда добавить.
