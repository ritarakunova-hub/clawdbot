# TAINA Knowledge Map — launch operating plan
Дата: 9 ноября 2026

## 1. Текущее продуктовое положение

TAINA Knowledge Map V1 — local-first инструмент структурированной диагностики одного процесса. Он помогает связать источники знаний, процессы, документы, ответственных, пробелы и задачи улучшения. Есть XLSX/CSV/JSON export, management summary, учебный пример, семишаговый маршрут и ручная проверка AI-сценария.

Это НЕ облачная база знаний, НЕ командный SaaS, НЕ документный парсер и НЕ AI/RAG-ассистент. Нет аккаунтов, server-side storage, cloud sync, team permissions, encryption at rest. Для V1 использовать только синтетические/обезличенные данные. Это ограничение должно быть заметно на сайте, в оплате, в onboarding и в buyer guide.

## 2. Рынок и стартовый ICP — гипотезы, не доказанные выводы

Начать с 2 узких сегментов:
1. Сервисные компании 15–100 сотрудников, где есть повторяющиеся процессы, несколько функций/отделов и зависимость от ключевых сотрудников.
2. Медицинские/диагностические компании и небольшие сети — только для обезличенной диагностики процессов; не собирать медицинские/пациентские сведения.

Покупатель: собственник, операционный директор, руководитель качества/обучения. Триггеры: быстрый рост, открытие филиала, замена ключевого сотрудника, аудит, ошибки из-за разных версий инструкций, подготовка к автоматизации/AI.

Главная задача позиционирования: не «ещё одна база документов», а «за один ограниченный пилот увидеть, как один важный процесс связан с источниками знаний, ответственными и пробелами».

Пока нет подтверждённой статистики готовности рынка платить и нет подтверждённых кейсов. Не публиковать выдуманные ROI, экономию времени, отзывы, число клиентов или проценты.

## 3. Модель запуска

### Этап A — закрытая проверка (первые 5–10 пользователей)
- Собрать заявки через Netlify Form на сайте.
- Отобрать 5–10 руководителей, согласных на короткий сценарий.
- Давать доступ только после объяснения local-first ограничений и безопасного набора данных.
- Наблюдать прохождение одного процесса: время до первого результата, где застревают, какой экспорт/отчёт нужен.
- Проводить короткие интервью после использования.
- Не брать оплату до прохождения обязательного релизного чек-листа и проверки способа выдачи лицензии/доступа.

### Этап B — первая коммерческая версия
- После release gate: оформить понятный оффер и условия лицензии.
- Цена-гипотеза из раннего плана: 1 490 ₽ разово за раннюю V1; проверить willingness-to-pay, не считать её утверждённой ценой до 5+ реальных оплат.
- Не продавать подписку, пока нет регулярной облачной ценности/обновлений.
- Показать ограничения рядом с ценой и checkout.
- Запросить разрешение отдельно, если хотим использовать отзыв или кейс.

### Этап C — масштабирование
- Только после доказанной активации/повторного использования решить, какие функции нужны чаще всего.
- Приоритеты для cloud/team V2 проверять интервью: аккаунты, синхронизация, права, командная работа, серверный backup, аудит.
- RAG/автоматизация — последующие продукты, не отвлекают от запуска Knowledge Map.

## 4. Воронка

Контент/партнёрская рекомендация/точечное обращение
→ продуктовая страница
→ заявка на ранний доступ
→ короткая квалификация по роли, размеру компании, процессу и чувствительности данных
→ guided first-run / 1 процесс
→ карта + управленческая сводка + export
→ интервью / обратная связь
→ платная V1 после release gate
→ запрос на следующий продукт только при выявленной потребности.

Activation event (North Star для пилота): пользователь создал один проект, добавил минимум один процесс, связал его с источником и ответственным, зафиксировал хотя бы один gap/подтверждение отсутствия пробелов и скачал JSON backup или XLSX. Это проверяемая продуктовая ценность, а не просто регистрация.

Основные метрики:
- visitor → submitted application;
- application → qualified;
- qualified → started;
- started → activation event;
- time-to-first-value;
- completion by journey step;
- number of support interventions per user;
- willingness-to-pay and paid conversion;
- export/backup completion;
- 7/30-day return (учитывая, что это инструмент периодической диагностики, а не ежедневный SaaS).

## 5. Автоматизация при минимальном времени основателя

Сначала не строить тяжёлый CRM и сложную цепочку. Минимальный стек:
1. Netlify Forms — сбор заявок и резервное хранение формы.
2. Netlify outgoing webhook → существующий n8n webhook (только после проверки безопасности и доступности n8n).
3. n8n — нормализовать поля, проверить согласие, присвоить статус, дедуплицировать по контакту.
4. Google Sheets — простая таблица лидов и статусов как временный CRM.
5. Telegram bot — уведомление о новой заявке и напоминание о follow-up.
6. Email-шаблоны — подтверждение заявки и инструкция по пилоту; не отправлять маркетинговые рассылки без отдельного согласия.
7. Еженедельный digest в Telegram — новые заявки, этапы, просроченные follow-up, activation metrics.

Не включать автоматическую оплату, выдачу доступа и запись чувствительных данных до выбора платёжного провайдера, юридических текстов и безопасного способа доставки продукта. Не хранить токены в клиентском JS или GitHub.

### Обязательные поля CRM
created_at, name, role, company, segment, contact, use_case, consent, source, stage, next_action, follow_up_at, started_at, activated_at, feedback, payment_status, notes_redacted.

### Статусы
new → qualified → invited → started → activated → feedback_due → paid / not_fit / paused.

## 6. Контентная система с низкой нагрузкой

Одна основная мысль в неделю → один большой материал → 3 коротких адаптации → 1 письмо/пост с CTA. Не создавать отдельный контент для каждой площадки.

Контентные опоры:
- риск знаний, которые живут в головах;
- процесс и карта источников/ответственности;
- практическая демонстрация приложения;
- честные ограничения V1 и безопасность;
- выводы из реальных пилотов.

Каналы на старте: Telegram как база аудитории; VK и YouTube Shorts как повторное распространение; личные точечные контакты и партнёры — для первых пользователей. Не покупать рекламу до подтверждения activation event и понятного conversion path.

## 7. Release gate — до публичной оплаты

Согласно RELEASE-CHECKLIST.md:
- pin exact dependency versions + lockfile;
- npm ci + npm audit;
- production build;
- Playwright E2E;
- browser checks: IndexedDB persistence, reload, backup, replace, merge, multi-tab, mobile 390px;
- XLSX open in Excel/LibreOffice;
- production CSP/security headers;
- inspect demo data, copy, and buyer guide.

До закрытия gate сайт может собирать заявки на ранний доступ, но не должен обещать production readiness, облачное хранение или автоматическую AI-аналитику.

## 8. Что не делать сейчас

- Не покупать VPS, CRM, email automation platform, paid ads или сложную аналитику.
- Не строить SaaS-аккаунты и командную синхронизацию без доказательства спроса.
- Не разрабатывать RAG параллельно с запуском карты.
- Не продавать «автоматическую оценку AI-готовности» как сертификат.
- Не заявлять ROI/экономию без измерений.
