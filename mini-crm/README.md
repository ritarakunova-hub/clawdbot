# TAINA mini-CRM — безопасный приём входящих заявок

Статус: **backend подготовлен к тестированию; production-подключение выключено**.

Сервис рассчитан на будущую связку:

Netlify Forms (только подтверждённые отправки) → подписанный webhook → валидация и дедупликация → Google Sheets → Telegram-уведомление.

## Важно: форма на текущем сайте не включена

На актуальном лендинге TAINA Process Diagnostic кнопки ведут в сообщения сообщества VK. Формы сбора заявок на этой странице сейчас нет. Этот CRM endpoint не подключён к production-сайту и не означает, что приём персональных данных уже запущен.

Не добавляйте форму и не направляйте в этот сервис реальные контакты до отдельной проверки:
- кто является оператором персональных данных и на каком основании обрабатываются данные;
- текста политики и корректного согласия в самой форме;
- места хранения Google Sheets и допустимости передачи туда данных;
- доступа к таблице, сроков хранения, удаления и резервного копирования;
- допустимости отправки контактных данных в Telegram.

Google Sheets и Telegram — внешние сервисы. До проверки требований и условий их использования тестировать CRM нужно только синтетическими данными. Этот README не является юридическим заключением.

## Что делает код

1. Принимает JSON от Netlify Forms на \`POST /webhook/netlify-lead\`.
2. Проверяет JWS из заголовка \`X-Webhook-Signature\` по секрету и хешу исходного тела запроса.
3. Проверяет стабильный ID отправки, наличие согласия, контакт и длины полей.
4. Проверяет, не сохранялась ли эта отправка раньше.
5. Записывает заявку в Google Sheets как обычные значения (\`RAW\`), не исполняя присланный текст как формулу.
6. Отправляет внутреннее уведомление в Telegram.
7. Сохраняет статус уведомления: \`pending\`, \`sending\`, \`sent\` или \`failed\`.

Netlify передаёт данные отправки в JSON; в payload обычно присутствуют \`id\`, \`form_name\`, \`created_at\` и объект \`data\`. Код поддерживает вложенную обёртку \`payload\` и читает идентификатор из \`payload.id\`/корневого \`id\`. [Пример payload в сообществе Netlify](https://answers.netlify.com/t/submission-created-payload-example/30054).

## Защита webhook

- Секрет обязателен. Если \`NETLIFY_JWS_SECRET\` отсутствует, endpoint отвечает \`503\`.
- Подпись проверяется по \`X-Webhook-Signature\` и исходным байтам тела запроса. Проверяются алгоритм HS256, issuer \`netlify\` и SHA-256 тела.
- Старый механизм \`?token=...\` удалён: секреты не передаются в query string.
- ID отправки хранится в таблице. Повторная доставка того же webhook не создаёт новую строку.
- Запросы обрабатываются последовательно в одном экземпляре приложения. Не запускайте несколько реплик одного mini-CRM с одной таблицей.
- Если состояние уведомления осталось \`sending\` или \`failed\`, сервис не повторяет отправку вслепую: сначала проверьте историю Telegram вручную. Только после подтверждения, что сообщения нет, оператор может вручную вернуть статус в \`pending\` и организовать повторную доставку того же проверенного события.
- В логах не выводятся имя, телефон, email или текст заявки.
- Внутреннее Telegram-уведомление содержит только ID заявки, форму и время; контактные поля в Telegram не отправляются.
- Повторный callback при статусе `sending` или `failed` не отправляет сообщение повторно: требуется ручная сверка.

Netlify описывает JWS-подпись исходящего HTTP webhook в документации по уведомлениям; для проверки подписи используются HS256, issuer \`netlify\` и SHA-256 тела запроса: [Netlify — Payload signature](https://docs.netlify.com/deploy/deploy-notifications/). Для form notification настройте JWS secret в UI и проверьте тестовую доставку до включения реальных данных.

## Структура Google Sheets

Создайте лист с именем \`Заявки\`. Первая строка — заголовки в следующем порядке:

| Колонка | Заголовок | Назначение |
|---|---|---|
| A | name | Имя |
| B | email | Email |
| C | phone | Телефон/мессенджер |
| D | message | Запрос |
| E | form_name | Название формы |
| F | received_at | Время отправки Netlify |
| G | status | Статус лида, начальное значение «Новая» |
| H | last_status_update | Время последнего обновления статуса |
| I | notes | Внутренние заметки |
| J | submission_id | ID отправки Netlify для дедупликации |
| K | consent_status | Подтверждение согласия, начальное значение «yes» |
| L | notification_status | Состояние уведомления в Telegram |

Существующие столбцы A:I не переставляйте. Если таблица уже содержит строки, добавьте заголовки J:L вручную, не удаляя старые данные. Перед подключением сделайте резервную копию.

Рекомендуемые значения для ручного ведения лида в колонке G:
- Новая
- Квалифицирована
- Предложение отправлено
- Ожидает ответа
- Пилот
- Оплачено
- Закрыта

## Подготовка Google Sheets

1. Создайте таблицу Google Sheets и лист \`Заявки\` с указанными колонками.
2. В Google Cloud включите Google Sheets API.
3. Создайте сервисный аккаунт и выдайте ему доступ редактора к этой таблице.
4. Скачанный JSON-ключ преобразуйте в base64 локально. Никому не отправляйте файл и строку.
5. В Amvera добавьте как секреты \`GOOGLE_SHEET_ID\` и \`GOOGLE_SERVICE_ACCOUNT_KEY_BASE64\`.

Ключ Google service account хранится только в переменной окружения. Не коммитьте его и не присылайте в чат.

## Подготовка Telegram

1. Создайте отдельного Telegram-бота через @BotFather.
2. Напишите боту первое сообщение.
3. Узнайте ID личного чата безопасным способом.
4. В Amvera добавьте \`TELEGRAM_BOT_TOKEN\` и \`TELEGRAM_CHAT_ID\` как секреты.
5. Для первого теста используйте отдельный тестовый чат.

Уведомление содержит только ограниченный фрагмент заявки, контакт и ID отправки. Не используйте личные медицинские, финансовые и иные чувствительные сведения в демонстрациях.

## Подготовка Netlify Forms (когда форма будет отдельно утверждена)

1. Создайте форму с осознанным согласием на обработку данных и ссылкой на утверждённую политику. Backend отклоняет отправки без положительного значения поля \`consent\` (допустимые значения: \`yes\`, \`on\`, \`true\`, \`1\`, «да», «согласен»).
2. В Netlify откройте Forms → Submission notifications → Add notification и выберите конкретную форму и HTTP POST webhook.
3. URL: \`https://ВАШ-ДОМЕН/webhook/netlify-lead\` — без токенов и секретов в URL.
4. Если интерфейс предлагает JWS secret token, задайте случайный секрет и тот же секрет сохраните на сервере в \`NETLIFY_JWS_SECRET\`.
5. Убедитесь, что тестовый webhook приходит с заголовком \`X-Webhook-Signature\` и что подпись принимается сервером.
6. Убедитесь, что Netlify отправляет только verified submissions.
7. Проведите тест на отдельной таблице и тестовом Telegram-чате, затем повторите одну и ту же отправку и проверьте, что второй строки не появилось.

Если для outgoing form webhook в вашем Netlify UI нельзя задать JWS secret, не включайте endpoint в production и не возвращайтесь к секрету в query string. Сначала выберите поддерживаемый защищённый способ передачи событий.

## Переменные окружения

- \`GOOGLE_SHEET_ID\` — ID таблицы.
- \`GOOGLE_SERVICE_ACCOUNT_KEY_BASE64\` — base64 от JSON-ключа service account.
- \`TELEGRAM_BOT_TOKEN\` — токен бота.
- \`TELEGRAM_CHAT_ID\` — личный или тестовый чат.
- \`NETLIFY_JWS_SECRET\` — секрет для JWS-подписи Netlify.
- \`PORT\` — порт приложения, обычно 3000.

См. \`.env.example\`. Не добавляйте реальные значения в Git, issue, pull request или переписку.

## Локальные тесты

\`\`\`bash
cp .env.example .env
npm ci

\`\`\`

Тесты используют синтетические payloads и локальную генерацию JWS. Они не вызывают Google Sheets, Telegram или Netlify. Входящая форма ограничена точным именем `taina-diagnostic`; свободный текст не сохраняется и не отправляется в уведомления.

Локальный запуск сервера:

npm start
\`\`\`

## Ограничения текущей версии

- Нет публичной формы на сайте и нет подтверждённого реального входящего webhook.
- Нет проверенного production-деплоя и end-to-end теста с Netlify, Google и Telegram.
- Нет полноценной CRM-панели; статусы и заметки ведутся в таблице.
- Нет автоматических напоминаний о следующем действии — это следующий этап после безопасного подключения и проверки реального потока.
- Дедупликация зависит от одного экземпляра приложения и одной таблицы.
- Для повторной доставки дубликата автоматически допускается только известный статус \`pending\`: он означает, что отправка в Telegram ещё не начиналась. Статусы \`sending\`, \`failed\` и любые неизвестные значения требуют ручной сверки; они не запускают повторную отправку.

До реального запуска нужен отдельный privacy/security review и тест на синтетических данных.
